# Автоматизация тестирования с помощью ИИ: оценка поисковой выдачи

Проект курса **Machine Learning System Design**, кейс Альфа-Банка. Подробности в дизайн-документе: [docs/ml_system_design_doc.md](docs/ml_system_design_doc.md).

## О чём проект

Клиент вводит запрос в поиске «Альфа-Онлайн» или «Альфа-Мобайл» и получает список фич банка: кредит наличными, переводы, вклады и т. д. Без раскрытия списка клиент видит только первые три результата, поэтому нужная фича должна стоять в топ-3.

Сейчас выдачу проверяют вручную и выборочно. Когда в поиск добавляют новые фичи, классификатор может деградировать на старых запросах, и такие просадки замечают не сразу.

Мы строим ИИ-агента, который снимает часть ручной проверки:

1. **Собирает выдачу** по списку запросов с учётом платформы и версии приложения, в первую очередь топ-3.
2. **Оценивает выдачу.** По каждому запросу выносит вердикт с объяснением, привязанным к конкретным позициям выдачи и интенту.
3. **Считает метрики** R3 и NDCG и подсвечивает просадки, например когда нужная фича съехала ниже топ-3.
4. **Показывает ход работы.** Шаги агента можно посмотреть и проверить их логику.

## Зачем

Команда поиска получает полный контроль качества по частым запросам вместо выборочного и узнаёт о просадках сразу после релиза, а не от клиентов. Критерий успеха из BRD — доля совпадений вердиктов агента с ручной разметкой.

## Как решаем

- **Этап 1. Калибровка оценщика.** LLM-судья на моделях AlfaGen оценивает готовые пары «запрос и выдача» и сверяется с разметкой команды. Сначала берём первые примеры, затем полный набор по 50–100 кейсов на интент. Бейзлайн — правило «ожидаемая фича интента есть в топ-3».
- **Этап 2. Рабочий прогон.** Агент сам вводит запросы в приложении на тестовом стенде, снимает выдачу и сверяет её со скриншотом через VLM. Затем оценивает выдачу, считает метрики детерминированным кодом и сравнивает их с базовым прогоном.
- **Проверяемость.** Каждый вердикт ссылается на позиции выдачи и требования. Спорные случаи проходят повторную проверку, фиксируется уверенность, а неуверенные вердикты уходят человеку.

## EDA (ДЗ 2)

EDA отвечает на четыре вопроса, от которых зависит агент: что тестируем (покрытие разделов набором запросов), что считать правильной выдачей (шкала разметки), что считать поломкой (порог тревоги и размер набора) и можно ли доверять LLM-судье. Данных банка пока нет: каталог фич написан вручную (допущение), метрики и просадки смотрим на выдаче WANDS, судью — на ESCI LLM-judged.

- Ноутбук: [notebooks/eda.ipynb](notebooks/eda.ipynb). Ответы и решения: [reports/eda/README.md](reports/eda/README.md).
- Датасеты и как их скачать: [data/README.md](data/README.md).
- Этапы решения по итогам EDA — раздел 2.3 [дизайн-документа](docs/ml_system_design_doc.md).

Как воспроизвести (CPU, около 15 секунд, данные загрузчики скачают сами):

```bash
uv sync --group eda
uv run jupyter nbconvert --to notebook --execute --inplace notebooks/eda.ipynb
```
